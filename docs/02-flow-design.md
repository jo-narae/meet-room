# 02. 사용 흐름 · 디자인 — meet-room

## 확정 사항

- 회의실 8개 (seed 고정, 등록 UI 없음) — 확정
- 운영 시간 09:00 ~ 19:00, 30분 단위 20슬롯 — (가정)
- 디자인: **A안 "관제탑"** — 화면 전체가 표. 사이드바 없음 — 확정

---

## 핵심 시나리오

### S1. 회의를 잡는 순간 — 데스크톱 (주 사용 흐름)

1. 지수는 목요일 오후 기획 리뷰를 잡아야 한다. 앱을 열면 로그인이 유지돼 바로 오늘 표가 뜬다.
2. 상단 날짜 화살표를 두 번 눌러 목요일로 이동한다. 표 전체가 목요일 예약으로 바뀐다.
3. 14:00~16:00이 통째로 비어 있는 방이 눈에 들어온다. **B회의실 14:00 칸을 누른 채 15:30까지 끌어내린다.**
4. 드래그 구간이 파랗게 칠해지고 "B회의실 · 14:00~16:00"이 뜬다. 목적에 "기획 리뷰"만 적고 확정.
5. 표에 지수 이름이 붙은 파란 블록이 자리잡는다. 걸린 시간 20초.

### S2. 회의 직전 1분 — 모바일 (다른 상황)

1. 회의가 3분 뒤인데 늘 쓰던 방에 다른 팀이 앉아 있다. 복도에서 휴대폰으로 앱을 연다.
2. 오늘 표가 뜨고 **지금 시각에 빨간 가로선**이 그어져 있다. 그 선 아래 빈칸만 보면 된다.
3. 가로로 한 번 밀어 D회의실이 지금부터 비어 있는 걸 확인한다.
4. 지금 시각이 포함된 칸을 누르면 시작 시간이 **현재 시각 기준으로 자동으로 채워진다**. 목적을 비우고 확정.
5. 회의실로 들어간다. 걸린 시간 15초.

## 화면 구조

```
[로그인] ──가입하기──> [회원가입]
    │
    └─로그인 성공─> [메인: 오늘의 회의실 표]  ← 앱의 90%
                        │
                        ├─ 빈칸 클릭/드래그 ─> (예약 입력 패널, 표 위에 겹침)
                        ├─ 내 예약 블록 클릭 ─> (상세 + 취소)
                        └─ 남의 예약 블록 클릭 ─> (예약자·목적만 표시, 취소 버튼 없음)
```

화면은 3개뿐이다. 예약 입력은 별도 페이지로 넘어가지 않고 표 위에 겹쳐 뜬다
— 페이지를 옮기면 어느 칸을 골랐는지 감각이 끊기기 때문.

미로그인 상태로 메인 주소에 접근하면 로그인 화면으로 보낸다.

### 레이아웃 규칙

- 상단 바 48px 고정. 그 아래 표가 화면 나머지를 전부 채운다.
- 시간 열(왼쪽)과 회의실 헤더 행(위)은 스크롤해도 고정(sticky).
- 한 슬롯 = 30분 = 세로 32px. 20슬롯이면 640px로 데스크톱 한 화면에 들어간다.
- 데스크톱: 8열이 한 화면. 모바일: 열 최소 폭 88px + 가로 스크롤.

### 차별점 구현 — "찾게 하지 않고 보이게 한다"

1. **현재 시각 빨간 가로선** — 표 위에 그어져 지금 이후 빈칸이 즉시 구분된다.
2. **지난 시간 흐리게** — 이미 지난 슬롯은 회색 처리하고 클릭을 막는다. 클릭할 곳만 선명하게 남는다.
3. **첫 진입 시 현재 시각 위치로 자동 스크롤.**
4. **현재 시각이 포함된 칸을 누르면 시작 시각이 지금으로 자동 채워진다** (S2의 15초를 만드는 장치).

### 상호작용 규칙

- 드래그는 **같은 회의실 세로 방향만**. 가로로 방을 넘나드는 선택은 불가.
- 드래그 중 남의 예약을 만나면 **그 앞에서 멈춘다** (넘어가서 이어지지 않는다).
- 예약 블록에는 목적 + 예약자 이름을 표시. 30분 한 칸이면 목적만 표시.
- 내 예약은 파랑 + 취소 버튼. 남의 예약은 남색 + 취소 버튼 없음.
