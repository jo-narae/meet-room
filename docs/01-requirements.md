# 01. 요구사항 — 회의실 예약 앱 (meet-room)

## 한 줄 정의

사내 구성원이 오늘의 회의실 빈 시간을 한 화면에서 보고, 로그인 후 즉시 잡는 웹앱.

## 공통 항목

| 항목 | 값 | 출처 |
|---|---|---|
| 주된 목적 | 팀 내부 사용 | (가정) |
| 주 사용 디바이스 | 반응형 — 데스크톱 예약 / 모바일 확인 | (가정) |
| 기술 스택 | Next.js 15 App Router + TypeScript + Tailwind | (가정) |
| 데이터 저장 | Supabase (Postgres) — 공유 데이터라 원격 DB 필수 | (가정) |
| 로그인 방식 | 아이디(이메일) + 비밀번호. 소셜 로그인 없음 | 확정 |
| 시간 예산 | 반나절 (인증 추가로 마일스톤 2개 증가) | 확정 |

## 핵심 문제

지금은 회의실이 비어 있는지 알 방법이 없다. 메신저에 "3층 회의실 지금 쓰나요?"를 던지거나,
직접 가서 문을 열어 본다. 그 결과 (1) 회의 시작이 5분씩 밀리고, (2) 두 팀이 같은 방에 들어가
한쪽이 쫓겨난다.

## 핵심 기능 (MVP)

1. **오늘 그리드** — 가로축 회의실, 세로축 시간(09:00~19:00, 30분 단위). 한 화면에서 빈칸이 보인다.
2. **빈칸 클릭 → 예약** — 회의 목적을 적고 확정. 예약자 이름은 로그인 계정에서 자동으로 채워진다.
3. **드래그로 시간대 선택** — 09:00 칸부터 10:30 칸까지 드래그하면 **09:00~11:00 예약 1건**이 생긴다
   (30분짜리 4건이 아니다). 제약 두 가지: **같은 회의실 안에서만** 드래그되고,
   **연속된 빈 시간만** 잡힌다(중간에 남의 예약이 있으면 그 앞에서 멈춘다).
4. **예약 취소** — 내가 만든 예약만 취소 가능. 남의 예약은 취소 버튼이 보이지 않는다.
5. **날짜 이동** — 오늘 기준 앞뒤로 이동해 미래 회의를 미리 잡는다.
6. **중복 방지** — 같은 방·같은 시간대에 예약이 겹치면 서버에서 거절한다.
7. **회원가입 / 로그인** — 이메일(사번 형태의 아이디도 가능) + 비밀번호. 로그인해야 예약 화면에 들어간다.

## 주 사용자와 사용 상황

- 사무직 팀원(팀장·실무자 구분 없음). 회의를 소집하는 쪽이 주로 연다.
- 사용 빈도는 하루 1~3회, 대부분 30초 안에 끝나는 방문.
- 여는 시점은 두 가지다. **(a) 회의 직전 1분** — 모바일로 "지금 빈 방"을 찾는다.
  **(b) 회의를 잡는 순간** — 데스크톱에서 며칠 뒤 시간대를 확보한다.

## 차별점

**빈 시간을 "찾게" 하지 않고 "보이게" 한다** — 첫 화면이 곧 오늘의 전체 가용 현황이고,
지금 시각이 그리드 위에 선으로 표시되어 클릭할 곳이 눈에 먼저 들어온다.

## 사용자 식별

**아이디(이메일) + 비밀번호 로그인.** 구글·카카오 같은 소셜 로그인은 쓰지 않는다. — 확정

- 계정 정보는 DB에 저장한다. 단, 회원 기능을 밑바닥부터 만들지 않고 Supabase에 이미 들어 있는
  회원 기능(Supabase Auth)을 쓴다. 비밀번호를 알아볼 수 없게 뭉개서 저장하는 처리와
  로그인 유지 처리가 이미 되어 있어 시간이 크게 절약된다.
- 가입 시 표시 이름(이름/팀)을 함께 받아 저장하고, 예약 카드에 그 이름이 뜬다.
- 로그인하지 않으면 예약 화면에 들어갈 수 없다. 주소를 직접 입력해도 로그인 화면으로 보낸다.
- 예약에는 만든 사람의 이름표가 붙고, **남의 예약은 취소·수정할 수 없다.**
  화면에서 버튼을 숨기는 것에 더해 DB에도 같은 규칙을 걸어둔다(RLS).
- 비밀번호 찾기(재설정 메일)는 v2로 미룬다. (가정)

## 범위 제외 (Out of Scope, v2 이후)

- 소셜 로그인, 비밀번호 재설정, 관리자 권한 구분
- 정기 회의(반복 일정)
- 회의실 등록/수정 UI (회의실 목록은 seed 데이터로 고정)
- 알림(슬랙·메일), 캘린더 연동
- 참석자 초대, 수용 인원 기반 추천
- 노쇼 자동 해제, 이용 통계
